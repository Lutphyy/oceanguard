LAPORAN TRAINING DAN EVALUASI MODEL

OCEANGUARD: DETEKSI SAMPAH LAUT MENGGUNAKAN YOLOv8

Mata Kuliah: Pengolahan Citra Digital — Tahun Ajaran Genap 2025/2026

1. Ringkasan Eksekutif

Laporan ini menyajikan hasil training dan evaluasi model YOLOv8 untuk sistem deteksi sampah laut OceanGuard. Model berhasil dilatih menggunakan dataset yang terdiri dari 3,028 gambar dengan 6 kategori sampah laut. Training dilakukan di Google Colab menggunakan GPU Tesla T4 dengan durasi 3 jam 4 menit (148 epochs dengan early stopping).

Hasil Utama:

  • mAP@50: 82.8% (melampaui target 80%)
  • Precision: 82.7% (excellent)
  • Recall: 74.5% (good)
  • F1 Score: 78.4% (good)
  • Status: Model siap untuk production deployment

5.3 Analisis Per Kelas

Kelas dengan Performa Terbaik (mAP > 85%):

  • electronics (94.3%): Performa outstanding dengan precision dan recall tinggi. Meskipun jumlah sampel paling sedikit (23 instances), model mampu mengenali objek elektronik dengan sangat baik karena karakteristik visual yang distinktif.

Kelas dengan Performa Baik (mAP 75-85%):

  • plastic (84.1%): Good performance dengan recall tinggi (80.0%). Model mampu mendeteksi sebagian besar objek plastik meskipun bentuknya bervariasi.
  • can (74.8%): Performa fair dengan ruang untuk improvement. Kaleng sering tertutup sedimen atau terkorosi sehingga lebih sulit dideteksi.

  • Augmentasi tambahan untuk underwater conditions: blur, noise, color distortion

5.4 Analisis Confusion Matrix

Confusion matrix memberikan insight mendalam tentang bagaimana model melakukan kesalahan klasifikasi. Matrix ini menunjukkan hubungan antara kelas yang diprediksi (sumbu horizontal) dengan kelas sebenarnya (sumbu vertikal).

Cara Membaca Confusion Matrix:

  • Diagonal (warna gelap): Prediksi yang benar (True Positives)
  • Off-diagonal (warna terang): Kesalahan klasifikasi
  • Baris: Kelas sebenarnya (ground truth)
  • Kolom: Kelas yang diprediksi model

5.5 Kesimpulan dari Confusion Matrix

Kekuatan Model:

  1. net_rope: Performa terbaik dengan 91% correct predictions dan minimal confusion
  2. electronics: Meskipun sampel sedikit, model sangat confident (94.3% mAP)
  3. bottle: Good performance dengan confusion minimal

Kelemahan Model:

  1. Missed Detections (Background): Total 108 objek tidak terdeteksi, dengan can (34) dan bottle (21) paling banyak terlewat
  2. Class "other": Recall sangat rendah (46.9%) dan banyak false positives (39)
  3. Confusion bottle-can: Ada overlap antara botol dan kaleng (5 misclassifications total)

Rekomendasi Berdasarkan Confusion Matrix:

  1. Reduce Missed Detections: Turunkan confidence threshold dari 0.25 ke 0.20 untuk mendeteksi lebih banyak objek (trade-off: lebih banyak false positives)
  2. Improve "can" detection: Tambah data augmentation untuk kondisi kaleng berkarat/tertutup sedimen
  3. Refine "other" class: Pecah menjadi sub-kategori atau hapus class ini untuk mengurangi confusion
  4. Hard negative mining: Tambah background samples yang mirip dengan objek untuk mengurangi false positives

6.1 Analisis Perbandingan

Model yang dilatih di Google Colab menunjukkan performa yang lebih baik dibandingkan baseline Roboflow dalam metrik utama (mAP@50). Berikut adalah analisis detail:

Keunggulan Model Kami:

  1. mAP@50 lebih tinggi (+1.2%): Ini adalah metrik paling penting untuk object detection. Model kami mampu mendeteksi objek dengan akurasi yang lebih baik pada threshold IoU 0.5.
  2. Recall lebih tinggi (+0.2%): Model kami mampu mendeteksi lebih banyak objek yang sebenarnya ada (fewer false negatives). Ini penting untuk aplikasi monitoring sampah laut agar tidak ada sampah yang terlewat.
  3. Kontrol penuh atas hyperparameters: Training di Colab memberikan fleksibilitas untuk fine-tuning hyperparameters sesuai kebutuhan.

Trade-off:

  1. Precision sedikit lebih rendah (-1.9%): Model kami menghasilkan sedikit lebih banyak false positives. Namun, trade-off ini acceptable karena dalam konteks monitoring sampah laut, lebih baik mendeteksi objek yang mungkin bukan sampah (false positive) daripada melewatkan sampah yang sebenarnya ada (false negative).
  2. F1 Score sedikit lebih rendah (-0.7%): Perbedaan ini sangat kecil dan masih dalam margin of error.

Kesimpulan: Model yang dilatih di Google Colab dengan konfigurasi optimal berhasil melampaui performa baseline Roboflow dalam metrik utama (mAP@50). Trade-off antara precision dan recall menunjukkan bahwa model kami lebih fokus pada mendeteksi sebanyak mungkin objek sampah (high recall) dengan tetap mempertahankan akurasi yang excellent (high precision).

8. Kendala Teknis yang Dihadapi

8.1 Masalah Numpy Compatibility

Masalah: Error ValueError: numpy.dtype size changed terjadi saat menjalankan training di Google Colab karena incompatibility antara versi numpy dan package lain (scipy, torch).

Solusi: Uninstall numpy dan scipy, lalu install numpy versi 1.26.4 yang compatible dengan PyTorch 2.11.0. Setelah itu, restart runtime untuk memastikan package yang baru ter-load. 

!pip uninstall -y numpy scipy
!pip install numpy==1.26.4
# Restart runtime: Runtime → Restart runtime

8.2 Masalah Class Order Mismatch

Masalah: Setelah deployment, model mendeteksi objek dengan label yang salah (misalnya botol terdeteksi sebagai plastik). Ini terjadi karena urutan class names di aplikasi tidak match dengan urutan class names di model.

Penyebab: Roboflow export dataset dengan class names dalam alphabetical order (bottle, can, electronics, net_rope, other, plastic), sedangkan aplikasi menggunakan urutan manual yang berbeda (plastic, bottle, can, net_rope, other, electronics).

Solusi: Check class order dari model menggunakan model.names, lalu update CLASS_NAMES di detector.py dengan urutan yang sama persis. 

# Check class order di Colab
from ultralytics import YOLO
model = YOLO('best.pt')
print(model.names)  # {0: 'bottle', 1: 'can', ...}

# Update detector.py dengan urutan yang benar
CLASS_NAMES = [
    "bottle",       # Index 0
    "can",          # Index 1
    "electronics",  # Index 2
    "net_rope",     # Index 3
    "other",        # Index 4
    "plastic",      # Index 5
]

8.3 Masalah Colab Disconnect

Masalah: Google Colab free tier memiliki idle timeout 90 menit dan maximum runtime 12 jam. Training yang lama berisiko disconnect dan kehilangan progress.

Solusi:

  • Gunakan auto-save checkpoint setiap 10 epochs (save_period=10)
  • Implementasi early stopping untuk menghindari training yang terlalu lama
  • Backup model weights ke Google Drive secara berkala
  • Gunakan keep-awake script untuk mencegah idle timeout

10. Kesimpulan

Training model YOLOv8 untuk sistem deteksi sampah laut OceanGuard telah berhasil dilakukan dengan hasil yang memuaskan. Model mencapai mAP@50 sebesar 82.8%, melampaui target yang ditetapkan (>80%) dan bahkan mengalahkan baseline Roboflow (+1.2%). Dengan precision 82.7% dan recall 74.5%, model menunjukkan balance yang baik antara akurasi deteksi dan coverage objek.

Performa per kelas menunjukkan bahwa model sangat baik dalam mendeteksi objek dengan karakteristik visual yang distinktif (electronics, net_rope, bottle) dengan mAP >85%. Kelas "other" memiliki performa terendah (67.9%) yang merupakan hasil expected mengingat variasi objek yang sangat tinggi dalam kategori ini.

Kecepatan inferensi ~102 FPS pada GPU Tesla T4 menunjukkan bahwa model sangat efisien dan mampu memproses video real-time. Bahkan pada CPU, YOLOv8 Nano dapat mencapai 20-30 FPS yang cukup untuk aplikasi web interaktif.

Beberapa kendala teknis yang dihadapi (numpy compatibility, class order mismatch, Colab disconnect) telah berhasil diatasi dengan solusi yang tepat. Model telah siap untuk deployment ke production dan dapat diintegrasikan ke dalam aplikasi web OceanGuard.
